# Validation Instructions

This document provides step-by-step instructions for deploying and validating the MySQL StatefulSet and Django ToDo application in Kubernetes.

---

## 1. Deploy Infrastructure

Run the bootstrap script to initialize the Kind cluster, build the Docker image, and apply all Kubernetes manifests:

```bash
./bootstrap.sh
```

---

## 2. Validate MySQL StatefulSet

### 2.1 Verify StatefulSet Pods and Service
Check that 3 replicas of MySQL pods are running in the `mysql` namespace and the headless service is active:

```bash
kubectl get statefulset,pods,svc -n mysql
```

Expected output should show `mysql-0`, `mysql-1`, `mysql-2` as `Running`, and service `mysql` with `ClusterIP: None`.

### 2.2 Verify PersistentVolumeClaims
Check that PVCs generated by `volumeClaimTemplates` are bound:

```bash
kubectl get pvc -n mysql
```

### 2.3 Validate Database Initialization (`init.sql`)
Verify that `init.sql` executed properly and created the `tododb` database:

```bash
kubectl exec -n mysql -it mysql-0 -- mysql -u todo_user -ptodo_password -e "SHOW DATABASES;"
```

`tododb` should be listed in the output.

---

## 3. Validate ToDo Application Deployment

### 3.1 Verify Deployment Pods
Ensure the application pods in the `todoapp` namespace are running and healthy:

```bash
kubectl get pods -n todoapp
```

### 3.2 Verify Application Secrets
Verify that the `app-secret` contains the connection configuration pointing to `mysql-0` (`mysql-0.mysql.mysql.svc.cluster.local`):

```bash
kubectl get secret app-secret -n todoapp -o jsonpath='{.data.HOST}' | base64 -d
```

### 3.3 Access Application
Port-forward the ToDo application service locally:

```bash
kubectl port-forward svc/todoapp-service 8080:80 -n todoapp
```

Open `http://localhost:8080` in your browser to verify that the application is functional and connected to the MySQL database.
